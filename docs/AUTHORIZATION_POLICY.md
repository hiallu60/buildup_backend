# 권한 정책표

현재 구현된 API와 서비스 코드를 기준으로 정리한 팀 공유용 권한 정책입니다. 복잡한 권한 엔진을 추가하지 않고, 시스템 역할·회사 역할·현장 역할과 객체 소유 여부만 사용합니다.

## 1. 권한 구조

### 시스템 역할

| 역할 | 의미 |
| --- | --- |
| `USER` | 일반 로그인 사용자입니다. 실제 업무 권한은 회사·현장 소속에서 결정됩니다. |
| `SYSTEM_ADMIN` | 운영 점검용 전체 관리자입니다. ID를 알고 있는 업무 객체의 서비스 권한 검사를 우회할 수 있습니다. 별도 관리자 화면과 전체 목록 API는 현재 제공하지 않습니다. |

### 회사 역할

| 역할 | 의미 |
| --- | --- |
| `HQ_MANAGER` | 본사 관리자입니다. 같은 회사 현장의 활성 구성원일 때 보고서 검토와 자재 요청 상태 변경 권한이 추가됩니다. |
| `HQ_MEMBER` | 일반 회사 구성원입니다. 회사 소속만으로 추가 업무 권한이 생기지 않으며 현장 역할을 따릅니다. |

### 현장 역할

| 역할 | 의미 |
| --- | --- |
| `OWNER` | 현장 소유자입니다. 현장 정보·참여 코드·구성원 역할을 관리하고 보고서·공정을 관리합니다. 현장마다 한 명입니다. |
| `MANAGER` | 현장 관리자입니다. 구성원 조회, 공정 관리, 보고서 검토, 자재 요청 처리를 수행합니다. 소유자 변경이나 구성원 역할 변경은 할 수 없습니다. |
| `WORKER` | 현장 작업자입니다. 현장 자료를 조회하고 보고서와 자재 요청을 작성합니다. |
| `VIEWER` | 조회 전용 구성원입니다. 현장·공정·보고서·자재 요청을 볼 수 있지만 작성·처리는 할 수 없습니다. |

`OWNER`는 현장 역할이고 `HQ_MANAGER`는 회사 역할이므로 서로 다른 개념입니다. 한 사용자가 두 역할을 함께 가질 수도 있습니다.

## 2. 공통 판정 순서

1. 공개 API가 아니면 유효한 Access Token이 필요합니다.
2. `SYSTEM_ADMIN` 우회가 구현된 업무라면 관리자에게 허용합니다.
3. 현장 업무는 활성 `site_members` 소속과 현장 역할을 확인합니다.
4. 보고서·첨부파일은 작성자 여부와 보고서 상태도 함께 확인합니다.
5. 알림과 디바이스 토큰은 현재 로그인한 사용자 본인의 데이터만 처리합니다.

권한이 없을 때 객체 존재 자체를 숨겨야 하는 조회는 `404`, 객체는 보이지만 해당 동작만 금지된 경우는 `403`을 사용합니다.

## 4. 객체 단위 권한

### 현장과 공정

- 현장 목록·상세 및 공정 조회는 해당 현장의 활성 구성원만 가능합니다.
- 현장 정보, 참여 코드, 구성원 역할은 `OWNER`만 변경합니다.
- `MANAGER`는 공정과 업무 데이터는 관리하지만 현장 소유권 영역은 변경하지 않습니다.
- 현장 가입 시 기본 역할은 `WORKER`이며, 역할 변경 API로 `OWNER`를 새로 지정할 수 없습니다.

### 보고서·사진·첨부파일

- 보고서 작성은 `OWNER`, `MANAGER`, `WORKER`에게 허용합니다.
- 목록·상세·사진·첨부파일 조회는 같은 현장의 모든 활성 구성원에게 허용합니다.
- 보고서 삭제와 사진·첨부파일 추가·삭제는 `PENDING` 보고서에 한해 작성자 또는 `OWNER`·`MANAGER`가 수행합니다.
- 승인·반려는 `OWNER`, `MANAGER`, 조건을 충족한 `HQ_MANAGER`, `SYSTEM_ADMIN`만 수행합니다.
- 검토가 끝난 보고서와 파일은 작성자라도 변경할 수 없습니다.

### 자재 요청

- 작성은 `OWNER`, `MANAGER`, `WORKER`에게 허용하고 조회는 모든 활성 현장 구성원에게 허용합니다.
- 상태 변경은 `OWNER`, `MANAGER`, 조건을 충족한 `HQ_MANAGER`, `SYSTEM_ADMIN`만 수행합니다.
- 작성자라는 이유만으로 요청을 승인·주문·배송 완료 처리할 수는 없습니다.

### 알림과 디바이스 토큰

- 알림 조회, 한 건 읽음, 전체 읽음은 항상 로그인 사용자 ID로 범위를 제한합니다.
- 다른 사용자의 알림 ID를 요청하면 찾을 수 없는 객체로 처리합니다.
- 디바이스 토큰 삭제는 현재 사용자가 소유한 토큰에만 적용합니다.

## 5. API 공개 범위

| 범위 | API |
| --- | --- |
| 인증 없이 사용 | `GET /api/health`, 회원가입, 로그인, 토큰 재발급, 로그아웃 |
| 로그인 필요 | 위 공개 API를 제외한 모든 `/api/**` |
| 조건부 진단 API | `GET /api/test/s3`는 설정으로 활성화된 경우에만 존재하며, 활성화되면 로그인 사용자가 호출할 수 있습니다. 운영에서는 기본값인 비활성 상태를 유지합니다. |

로그아웃은 Access Token이 아니라 Refresh Token을 폐기하는 요청이므로 현재 공개 API로 유지합니다.

현재 단계에서는 별도 권한 테이블, 동적 권한 설정 화면, 복잡한 정책 엔진을 도입하지 않습니다. 새로운 API를 추가할 때는 이 표에서 가장 가까운 객체 규칙을 서비스 계층에 적용하고, 최소한 허용 1건과 거부 1건을 테스트합니다.
